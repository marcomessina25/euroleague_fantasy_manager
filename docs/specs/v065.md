# V0.6.5 — Release Hardening, League-Aware Data Paths & EuroCup Ingestion

> **Status:** Planned — active on branch `v065` (created from `main` after PR #8/#9 merged V0.6).
> **Planning baseline:** 2026-09-29
> **Objective:** Make V0.6 trustworthy for day-to-day use on **both** EuroLeague and EuroCup teams by closing correctness gaps, making every data path league-aware, operationalizing EuroCup ingestion and hardening the workstation.
> **Companion document:** [`v065_potential_bugs.md`](v065_potential_bugs.md) — the bug/risk register with severities, dispositions and regression coverage.
> **Rule:** V0.6.5 is a **hardening release**. It adds no new prediction models, optimizer algorithms or autonomous behaviour.

---

## 1. Why V0.6.5 exists

V0.6 introduced the multi-league foundation, six isolated teams, the Manager Dossier, deterministic strategic analysis and the grounded Copilot. Two rounds of PR review showed that the **architecture is sound but several paths were not yet league-aware or were silently wrong**:

- the web workstation read whichever league's snapshot was newest (fixed in `f6a144a`);
- the dossier called optimizer methods that did not exist and swallowed the error (fixed in `f6a144a`);
- the CLI data commands (`report`, `players`, `squad`, `fixtures`, `lineup`, `suggest-trades`, `validate-trades`, `import-squad`) **still** read the newest snapshot of *any* league;
- EuroCup squads cannot be imported reliably;
- several edge cases (postponed fixtures, players leaving the competition, coach changes, bank boundaries) have never been exercised by tests;
- the workstation builds HTML from API-sourced strings without escaping;
- version and provenance metadata are stale or incomplete.

Following the pattern established by `fpl-manager` V0.65, this release is organised as a **potential-bugs register plus targeted workstreams**. Every register item must be reproduced, classified and either fixed with regression coverage or explicitly closed.

```text
V0.6 merged (PR #8/#9)
      ↓
review fixes landed on v065 (f6a144a)
      ↓
V0.6.5 workstreams W1–W8
      ↓
register fully dispositioned
      ↓
regression gate + manual workstation smoke test
      ↓
merge v065 → main
      ↓
V0.7
```

---

## 2. Principles

1. **League is always explicit or inherited, never guessed.** Every read of snapshot or projection data resolves a league in this order: explicit `--league`/request parameter → the active/target team's league → `euroleague` default. Reading "the newest snapshot of any league" is not allowed in user-facing paths.
2. **Fail loudly, not plausibly.** A missing player, an unknown league or a failed optimizer call must surface as an explicit error or warning, never as a silently shortened squad or an empty section that looks valid.
3. **Deterministic engine stays authoritative.** No change in V0.6.5 alters projections or optimizer objectives except to correct a verified bug.
4. **Every `FIXED` has a test.** A register item is only `FIXED` when a regression test (or, for GUI-only behaviour, a recorded manual verification) covers it.
5. **No network in tests.** Live-API behaviour is exercised with recorded/synthetic payloads; live calls are a documented manual check.
6. **Scope freeze.** Anything not listed here goes to V0.7+.

## 4. Workstreams

Each workstream lists goal, tasks, files, acceptance criteria and required tests. Register IDs in brackets refer to [`v065_potential_bugs.md`](v065_potential_bugs.md).

### W1 — League-aware CLI and data-access layer (P1)

**Goal:** no CLI command can read the wrong league's data. [BUG-LG-003]

**Tasks**

1. Add one helper that resolves the league for a command, `resolve_command_league(args, team_service) -> League`, using the precedence in §2.1. The global `--league` flag must default to *unset* (today it defaults to EuroLeague, which hides the active team's league).
2. Thread `league_id` through the module functions that call `SnapshotStore` without it:
   - `expected_points.project_all_players` (`load_latest_players/teams/fixtures`)
   - `fixtures.analyze_team_fixtures`, `fixtures.analyze_squad_fixtures`
   - `squad_report.generate_squad_report`
   - `suggest_transfers.suggest_trades`
   - `lineup.generate_lineup_report`
   - `import_squad.search_player_exact_or_single` / `import_squad_from_file`
   - `cli.py` direct calls in `players` and `validate-trades`
   - `SnapshotStore.get_latest_summary(league_id=None)` for `report`
3. Keep `league_id=None` ("latest of any league") only for internal maintenance code; mark it as such in the `SnapshotStore` docstrings.
4. Print the resolved league in every command's header line (e.g. `League: EUROCUP (from active team)`).

**Acceptance criteria**

- With a database whose newest snapshot is EuroCup and an active EuroLeague team, every command in the list above reports EuroLeague data. The reverse also holds.
- An explicit `--league` always wins over the active team.

**Tests**

- One parametrized test over all affected commands using a two-league database (reuse `_league_payload` from `tests/test_v06_strategic_intelligence.py`), asserting that no player ID from the other league appears in the output.
- Unit test for the precedence rules of `resolve_command_league`.

### W2 — EuroCup ingestion pipeline (P1)

**Goal:** `elf update --league eurocup` and the GUI "Update Data" produce a correct, isolated EuroCup snapshot, and season codes are not hard-coded. [BUG-LG-005, BUG-DATA-001]

**Tasks**

1. Make `_resolve_league` strict: unknown values raise a clear error (CLI exit 2, API 400) instead of silently mapping to EuroLeague. Reuse `League.from_str`.
2. Stop hard-coding `E2026`/`U2026`: resolve the season code from the fantasy `config` payload when available, with an explicit `--season-code` override. Record the source (config vs override) in the snapshot summary.
3. Verify `fetch_official_clubs` for competition `U`. Derive the club count from the feed rather than asserting a fixed number, and store it in the summary.
4. Schema v3 migration: add an index `snapshots(league_id, id)`. The migration must be idempotent and covered by the existing schema-version mechanism.
5. `elf report` / GUI summary show the league and season code of the snapshot being reported.
6. Manual live check (not a test): run `elf update --league eurocup` and `elf update --league euroleague` against the real API once and record date, counts and any anomalies in the register.

**Acceptance criteria**

- Two consecutive updates (EuroCup then EuroLeague) leave both leagues independently queryable.
- `elf update --league nba` fails with a readable message; the API returns 400.
- No code path contains a literal `E2026`/`U2026` except defaults documented as fallbacks.

**Tests**

- Mocked-HTTP ingestion test for EuroCup (`league_id=11`, competition `U`) asserting stored `league_id`, `competition_code`, `season_code`.
- Schema v3 migration idempotence test (run twice; the index exists once; the version is 3).
- Invalid league tests for the CLI and `/api/workstation/update-data`.

### W3 — EuroCup squad import (P1)

**Goal:** a EuroCup roster can be imported and is never matched against EuroLeague players. [BUG-LG-004]

**Tasks**

1. `import-squad` resolves the league (W1 helper) and searches only that league's latest snapshot.
2. `current_squad.json` is written with the resolved `league_id`.
3. Loading a squad file whose `league_id` differs from the resolved league produces an explicit error (or warning plus confirmation in interactive use).
4. Update `docs/squad_import.md` with a EuroCup example.

**Acceptance criteria**

- Importing the same `players.txt` against a two-league database with `--league eurocup` resolves only EuroCup IDs.
- Ambiguous or not-found names report the league searched.

**Tests**

- EuroCup import round-trip; league-mismatch error; a name that exists only in the other league returns not-found.

### W4 — Edge-case and rules audit (P1/P2)

**Goal:** known real-world situations behave predictably and are covered by tests. Each item starts as `NEEDS VERIFICATION` in the register.

| ID | Scenario | Expected behaviour to verify / implement |
| --- | --- | --- |
| BUG-EDGE-001 | Fixture **postponed/cancelled** mid-round | Confirm the Dunkest/IncrowdSports status vocabulary. Players whose game will not be played this round get `expected_fp = 0` and are flagged, and are not treated as future substitution candidates. |
| BUG-EDGE-002 | Squad player **left the competition** (missing from the latest snapshot) | One consistent policy across `squad_report` (currently raises), `suggest_trades` (currently drops silently → a 10-man squad), `lineup`/`fixtures` (currently skip) and `_resolve_squad_contracts` (currently synthesizes 10 FP). Proposed: keep the unit, project 0 FP, flag it as "unavailable — sell candidate". |
| BUG-EDGE-003 | **Head coach replaced** mid-season | The old coach ID disappears and a new ID appears for the same club. Covered by the EDGE-002 policy; the transfer optimizer must be able to replace the coach. |
| BUG-EDGE-004 | **Bank boundaries** (exactly 0.0 cr; post-trade −0.1 cr) | 0.0 is legal and −0.1 is rejected, in `validate_trades`, `TransferOptimizer`, the team API trade route and the GUI. |
| BUG-RULE-002 | **Played starter moved to the bench** (including a captain who has just lost the armband) | Verify against the official rules whether a starter whose game has started may be moved to the bench. Adjust `IntraRoundSubstitutionOptimizer` only if the rule differs. |
| BUG-EDGE-005 | **Three-turn rounds** (T1→T2→T3) | The optimizer and dossier handle `turn_number = 3` and captain switches across T2→T3. |
| BUG-EDGE-006 | **Round rollover** while a team is mid-round | The dashboard, dossier and advise all use the team's `round_number`; there is no mixed-round projection. |

**Rule:** where the official rule is unknown, ask the product owner before changing behaviour (as was done for the captaincy rule). Record the answer and its date in the register.

**Tests:** one focused unit/integration test per row, using synthetic payloads.

### W5 — Web/API hardening (P1/P2)

**Goal:** the workstation is safe against untrusted strings and returns correct HTTP semantics. [BUG-SEC-002, BUG-API-001, BUG-API-002]

**Tasks**

1. Add a single `escapeHtml()` helper in `app.js` and apply it to every `innerHTML` template that interpolates data from the API, the fantasy feed or the LLM: player/team names, team codes, strategic-analysis strings, checklist details, transfer chips, modal fields. Prefer `textContent` where no markup is needed.
2. Add a FastAPI dependency `parse_league()` that turns invalid values into 400. Use it in `/players`, `/players/{id}`, `/initial-team/suggest`, `/update-data` and team creation. Today `/players?league=nba` and `/players/{id}?league=nba` return **500** (verified 2026-09-29).
3. Scope the `/players/{id}` snapshot row lookup to the requested league. Today it takes the newest row for that ID across all snapshots.
4. Audit remaining `except Exception → 400` handlers. Server faults (e.g. the decision-audit write failure) must be 5xx; validation problems must be 4xx.

**Acceptance criteria**

- A player named `<img src=x onerror=alert(1)>` in a synthetic snapshot renders as text in the court view, Trade Studio, team builder, player modal and Intelligence tab.
- No endpoint returns 500 for a malformed `league`.

**Tests**

- API tests for invalid league on every league-accepting endpoint.
- A static test that fails if `app.js` interpolates a known-unsafe field into `innerHTML` without `escapeHtml(` (a simple regex guard, no new tooling).
- A manual browser check of the XSS payload, recorded in the register.

### W6 — Provenance, versioning and metadata consistency (P2)

**Goal:** what the system reports about itself is true. [BUG-PROV-001..003, BUG-LLM-001..002]

**Tasks**

1. Single source of version: `__version__` (currently `0.5.0`) and `pyproject.toml` (currently `0.6.0`) must agree. Read the version via `importlib.metadata` with a fallback, and bump it to `0.6.5` at release.
2. The dossier `content_hash` must cover the canonical serialized quantitative content: lineup units and their numbers, transfer options, intra-round option, valuations, league, round and ruleset. It must exclude `dossier_id`/`generated_at`. Today it hashes only `team_id:round:total:len(transfers)`.
3. Replace the hard-coded provenance strings `prediction_model="decomposed_v051"` and `optimizer_engine="bounded_milp_v051"` with the identifiers actually used (model name from `PredictionService`, optimizer/risk configuration from `OptimizationService`).
4. Provider discovery (`list_available_providers`) must report the same `default_model` as each provider class (Gemini: `2.0-flash` vs `2.5-flash`; heuristic naming).
5. Document that the heuristic provider ignores the tier, and include the tier in its output metadata (the register marks this `ACCEPTED RISK`).

**Tests**

- Hash changes when any projected number changes and stays equal across runs with different timestamps.
- `__version__ == importlib.metadata.version(...)`.
- For each provider, discovery `default_model` == class default.

### W7 — Quality gates and release engineering (P2)

**Goal:** regressions are caught automatically. [BUG-QA-001]

**Tasks**

1. Add a GitHub Actions workflow that runs `pytest` and `node --check` on `app.js` for pushes and PRs to `main`/`v0*`. This is the first CI in the repository; keep it minimal.
2. Add a documented manual GUI smoke-test script to the register covering: create a EuroLeague team, create a EuroCup team, switch teams, Update Data per league, Trade Studio, Intelligence tab (all three tiers, heuristic provider), and the XSS payload check.
3. PR and release notes quote test counts only from an actual run, never from a hand-maintained number.

**Out of scope for V0.6.5:** a JavaScript unit-test framework or Playwright suite. Evaluate it in V0.7 if GUI regressions recur.

### W8 — Documentation (P2)

1. Keep `v065_potential_bugs.md` in sync with the branch. Every item ends with a final disposition.
2. `docs/roadmap.md`: V0.6 marked merged; V0.6.5 status tracks this spec.
3. README: EuroCup workflow (`elf update --league eurocup`, `elf team create --league eurocup`, `elf import-squad --league eurocup`), the league resolution rule, and the captaincy rule.
4. `docs/squad_import.md`: EuroCup example (W3).
5. `docs/architecture.md`: the league-resolution precedence (§2.1) and the "no any-league reads in user paths" rule.

## 8. Definition of Done

A user can:

1. Update EuroLeague and EuroCup data independently, from the CLI or the GUI.
2. Import, create and manage EuroCup teams exactly like EuroLeague teams.
3. Run any CLI command or workstation view and always see the correct league's data.
4. Rely on postponed games, departed players, coach changes and bank edges behaving predictably and visibly.
5. Use the workstation without API- or LLM-sourced strings being interpreted as HTML.
6. Trust version, provenance and provider metadata.
7. See every V0.6.5 risk item with a final, test-backed disposition.

> **V0.6.5 makes V0.6 dependable for both leagues without expanding what the engine does.**
