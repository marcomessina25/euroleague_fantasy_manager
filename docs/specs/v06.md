# V0.6 — Strategic Intelligence & LLM Copilot

> **Status:** Planned  
> **Objective:** Add strategic interpretation around the deterministic engine without allowing an LLM to become the source of truth, rules engine, prediction engine, or optimizer.  
> **Architecture:** Mirror the proven LLM/copilot patterns from `fpl-manager` v0.6.5.

## 1. Core Architecture

```text
data → rules/state → prediction → valuation → optimization
                                      ↓
                               Manager Dossier
                                      ↓
                         strategic analysis / LLM
                                      ↓
                                   human
```

The deterministic stack remains authoritative.

The LLM may explain, challenge, compare and interpret. It must not silently change rules, predictions, scores, legality or persistent team state.

## 2. Manager Dossier

Create a deterministic, structured dossier containing:

- **Team/Squad/Bank/Round/Turn State:** Current squad units, bank credits, transfers remaining, league (EuroLeague or EuroCup), round number
- **Projections:** Expected fantasy points, expected minutes, play probability, FP/min, uncertainty bands
- **Valuations:** Price, value, PAR, efficiency metrics
- **Optimizer Recommendations:** Lineup recommendation, legal alternatives, risk modes
- **Transfer Packages:** Multi-option recommendations ranked by net transfer value
- **Intra-Round Alternatives:** T1 → T2 → T3 substitution options with projected gains
- **Multi-Round Candidates:** Forward-looking squad plans
- **Relevant Schedule/Context:** Fixture list, team news, opponent context
- **Prediction and Optimizer Provenance:** Model versions, cutoff timestamps, configuration snapshots

Every quantitative fact must remain traceable to its source/run/cutoff where practical.

**Multi-League Support:** Dossier schema must be league-agnostic. Position names, role abbreviations, and cap rules vary between EuroLeague and EuroCup but the dossier structure is identical.

## 3. Strategic Analysis Layer

Add optional deterministic analysis before invoking LLM:

- **Assumption Breakdown:** Top 3–5 assumptions ranked by impact (participation probability, minutes band, efficiency, location multiplier)
- **Sensitivity Analysis:** Show decision changes if each key assumption flips
- **Devil's Advocate Checklist:**
  - Rule Check: Is this lineup legal?
  - Forecast Check: Are projections plausible?
  - Alternative Check: Missing an obvious better option?
  - Regret Check: What's the worst-case scenario?
  - Context Check: What's changed since last decision?

This layer works with LLM disabled and provides deterministic signals before strategic interpretation.

## 4. LLM Copilot Layer

The optional LLM layer can provide:

- **Manager Briefing:** High-level summary of current state, recommendation, and main alternatives
- **Explanation of Optimizer Choices:** Why this lineup? Why this captain? Why these transfers?
- **Alternative Comparison:** Structured comparison of top 3 transfer options or intra-round sub scenarios
- **Devil's-Advocate Critique:** Challenge assumptions, highlight risks, suggest stress-test scenarios
- **Risk/Uncertainty Interpretation:** Explain confidence bands, calibration, and edge cases
- **Scenario Comparison:** "What if we trade this player?" or "What if we wait until next round?"
- **Change Detection:** "Here's what changed since the last decision"

**Implementation Patterns (from fpl-manager v0.6.5):**
- Provider abstraction to avoid vendor lock-in (OpenAI, Claude, OpenRouter, local)
- Cost/latency tier: fast (local), standard (API <1s), extended (2–10s reasoning)
- Graceful fallback if provider fails; deterministic analysis remains available
- Copilot must work with LLM provider disabled

## 5. Multi-League Support in V0.6

V0.6 implements league abstraction at the **dossier and analysis layer**:

- Dossier schema is competition-agnostic
- Position names and role abbreviations are competition-specific adapters
- Ruleset (cap, formation, scoring) is queried dynamically based on league
- Strategic analysis works identically for EuroLeague and EuroCup teams
- Same LLM prompts/analysis for both leagues with league-specific context injected

**Scope:** V0.6 focuses on EuroLeague with EuroCup dossier/analysis compatibility prepared; full EuroCup feature parity deferred to V0.9.

## 6. Human Control

V0.6 must not:

- execute transfers automatically;
- mutate team state without confirmation;
- override official rules;
- replace optimizer calculations;
- invent numerical facts.

**Workflow:**

```text
engine → dossier → analysis → human → confirmed decision
```

All decisions remain with the human.

## 7. Provenance

Record, where applicable:

- LLM provider (OpenAI, Claude, OpenRouter, local, etc.)
- Model name and version
- Prompt version and content hash
- Dossier version and generation timestamp
- Configuration snapshot (risk mode, transfer budget, league, etc.)
- Analysis tier/cost (fast/standard/extended)
- Timestamp of analysis

Never store secrets or API keys in provenance records.

## 8. Robustness (from fpl-manager experience)

- **Provider Failure Isolation:** If LLM provider fails, analysis gracefully falls back to deterministic checklist without contaminating team state
- **Numerical Consistency Verification:** All LLM claims about projections/values must be checkable against the dossier
- **Rule Consistency Check:** Verify LLM recommendations respect official rules before presenting to human
- **Factual Consistency Testing:** Compare LLM narrative against dossier facts; flag contradictions

## 9. Evaluation Criteria (not fantasy performance)

Evaluate the copilot for:

- **Factual Consistency:** Does the narrative match the dossier?
- **Rule Consistency:** Do recommendations violate official rules?
- **Numerical Consistency:** Can all numbers be traced back to the dossier?
- **Correct Representation of Alternatives:** Are top 3 transfer options accurately summarized?
- **Usefulness:** Is the analysis actionable and insightful?
- **Latency:** Does analysis complete within acceptable time budget (5–10s for interactive use)?

Do not claim that LLM advice improves fantasy performance merely because the prose is preferred.

- [ ] Provenance complete and immutable
- [ ] LLM-disabled path works without degradation
- [ ] Provider failure cannot corrupt team state

- [ ] Numerical claims in LLM output checkable against dossier
- [ ] Prompt/model provenance recorded for all analyses
- [ ] Multi-league dossier structure tested for EuroLeague and EuroCup

## 11. Out of Scope (V0.6)

- Autonomous management or decision execution
- Automatic transfer application
- New prediction models or components
- New optimizer algorithms
- Full historical sequential replay (deferred to V0.7)
- EuroCup feature parity (deferred to V0.9)
- Multi-provider orchestration or routing

## 12. Definition of Done

A user can:

1. Select a team (EuroLeague or EuroCup)
2. Generate a deterministic dossier
3. Inspect recommendations and alternatives
4. Request strategic analysis (deterministic or with LLM)
5. Inspect evidence and trace claims back to source data
6. Request LLM challenge or alternative scenario
7. Make the final human decision
8. Log the decision with full provenance

> **V0.6 adds intelligence around the engine, not intelligence instead of the engine.**
