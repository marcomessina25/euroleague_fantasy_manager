# V1.0 — Mature Multi-League Fantasy Decision Platform

**Status:** Planned  
**Baseline:** V0.9 / PR #14  
**Target branch:** `v10`  
**Planning baseline:** 2026-10-03  
**Active competitions:** EuroLeague E2026, EuroCup U2026  
**Scope:** Regular season; playoffs remain outside the V1.0 contract unless explicitly added later.

---

# 1. Executive definition

V1.0 is a **quality and maturity milestone**, not a major feature expansion.

The objective is to prove that the capabilities developed through V0.1–V0.9 form one coherent, reproducible, point-in-time-correct, auditable and operational fantasy decision platform for both EuroLeague and EuroCup.

V1.0 must establish that:

1. deterministic fantasy rules remain authoritative;
2. predictions are point-in-time correct and reproducible;
3. the V0.9 learned availability/minutes models are genuinely trained and evaluated on historical data;
4. lineup, transfer and sequential optimization are validated against appropriate correctness or replay oracles;
5. every important recommendation can be traced from state → prediction → optimization → human decision → actual outcome → regret;
6. six isolated teams can operate simultaneously across both competitions;
7. EuroLeague and EuroCup share the same engine and differ only through explicit rules/configuration;
8. the CLI and workstation are reliable enough for real round-by-round use;
9. the LLM Copilot remains optional, grounded and non-authoritative;
10. an automated V1.0 certification suite can determine whether the release is ready.

The core philosophy remains:

> **Intelligence around the engine, not intelligence instead of the engine.**

---

# 2. What V1.0 is — and is not

## V1.0 is

- a maturity release;
- an architecture-contract release;
- a scientific validation release;
- a reproducibility release;
- a cross-league integrity release;
- a closed-loop auditability release;
- a production-hardening release.

## V1.0 is not

- a new prediction-model generation;
- a new optimization generation;
- an autonomous fantasy agent;
- an LLM-first architecture;
- a reinforcement-learning project;
- a major GUI redesign;
- a replacement for the V0.9 learned models;
- a giant feature-engineering exercise.

If a proposed change does not materially improve correctness, reproducibility, validation, auditability, isolation, reliability or release certification, it should normally be deferred to V1.1+.

The final V1.0 system should have a clear contract chain:

```text
Official / historical data
          ↓
Point-in-time snapshot
          ↓
Deterministic fantasy state + rules
          ↓
Prediction contract
          ↓
Valuation / uncertainty / context
          ↓
Optimization
          ↓
Recommendation / Manager Dossier
          ↓
Human decision
          ↓
Actual outcome
          ↓
Evaluation / regret / drift
```

The LLM Copilot operates alongside the deterministic layers:

```text
Deterministic state
       ↓
Deterministic analysis
       ↓
LLM interpretation/challenge
       ↓
Human decision
```

The LLM must never silently modify authoritative state, rules, predictions or optimizer output.

# 24. V1.0 completion statement

When V1.0 is released, the project should be able to make the following factual statement:

> **EuroLeague Fantasy Manager is a reproducible, point-in-time-aware, multi-league fantasy decision platform that combines deterministic fantasy rules, validated statistical predictions, optimization, decision logging, historical replay and optional grounded strategic interpretation.**

It should **not** claim:

- that the system always makes optimal decisions;
- that the learned model is universally superior;
- that the LLM is authoritative;
- that optimization is globally exact where it is approximate;
- that historical benchmark results guarantee future performance.
