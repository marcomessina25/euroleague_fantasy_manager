# V0.2.5 — Historical Evaluation Foundation

> **Purpose:** Turn the V0.2 heuristic decision-support layer into a measurable quantitative system before adding more model complexity.
>
> **Core principle:** V0.2.5 is not about building a better predictor yet. It is about building the machinery that can tell us, rigorously and reproducibly, whether a predictor is better.
>
> **Target outcome:** At the end of V0.2.5 we should be able to say, for any historical round for which point-in-time inputs are available:
>
> 1. what information the manager would have had at decision time;
> 2. what V0.2 would have predicted;
> 3. what simple baselines would have predicted;
> 4. what actually happened;
> 5. how each method performed;
> 6. whether the differences are large enough to justify a more sophisticated V0.3 model.

---

# 1. Scope

V0.2.5 introduces four capabilities:

```text
Historical raw data
        ↓
Point-in-time dataset
        ↓
Baseline predictions
        ↓
Actual outcomes
        ↓
Metrics + reports
```

It does **not** yet attempt to build the final predictive model.

The release should establish a clean experimental framework for:

- player-game historical data;
- point-in-time feature generation;
- prediction targets;
- V0.2 xPDK reproduction;
- simple statistical baselines;
- walk-forward evaluation;
- prediction metrics;
- ranking metrics;
- fantasy-decision metrics;
- model/version provenance.

---

# 2. Non-goals

Do not include the following in V0.2.5:

- deep learning;
- LLM-based prediction;
- neural networks;
- news/NLP injury models;
- ownership prediction;
- sophisticated transfer optimization;
- multi-round planning;
- exact live Turn substitution optimization;
- GUI;
- EuroCup activation;
- production-grade cloud infrastructure.

The purpose is to establish scientific measurement first.

---

# 3. Release acceptance criteria

V0.2.5 is complete only when all of the following are true:

### Data
- [x] At least 3 historical seasons can be represented in a normalized player-game dataset.
- [x] Each player-game record has a stable player identifier.
- [x] Each game has stable game/round/team/opponent identifiers.
- [x] Historical snapshots can be associated with the information available before the game/round.
- [x] Duplicate games and duplicate player-game records are detected.

### Targets
- [x] Actual fantasy score can be reconstructed from authoritative game statistics where possible.
- [x] Head Coach outcomes have a separate target definition.
- [x] Missed/unused players are explicitly represented rather than silently dropped.
- [x] DNP/inactive/unknown cases have distinct statuses.

### Feature generation
- [x] Rolling features are point-in-time safe.
- [x] No future game information can leak into a feature.
- [x] Features can be generated for a historical round using only data available before that round.

### Baselines
- [x] Season-average baseline exists.
- [x] Last-N-game baseline exists.
- [x] EWMA baseline exists.
- [x] V0.2 xPDK can be reproduced from historical point-in-time data.

### Evaluation
- [x] MAE and RMSE are implemented.
- [x] Spearman rank correlation is implemented.
- [x] Top-K ranking metrics are implemented.
- [x] Evaluation can be run round-by-round.
- [x] Aggregate metrics include confidence/sample-size information.
- [x] Results are saved with model version and dataset version.

### Reproducibility
- [x] A historical evaluation can be rerun from a clean database snapshot.
- [x] Reports identify the training/data cutoff.
- [x] Tests prevent accidental future-data leakage.

# 5. Point-in-time principle

This is the most important technical rule of V0.2.5.

For a prediction made before Round R:

```text
Allowed:
    all information with timestamp < decision cutoff

Forbidden:
    Round R player statistics
    Round R final scores
    post-game prices
    post-round injury/status information
    future schedule-derived outcomes
```

The system should make this invariant testable.

Example:

```python
features = build_features(
    player_id=123,
    decision_cutoff="2025-11-01T12:00:00"
)
```

The function must never query data newer than the cutoff.

# 7. Target definition

## 7.1 Player target

Primary target:

```text
actual_fantasy_points
```

Secondary targets:

```text
actual_pir
minutes
starter_status
```

The first V0.2.5 objective is fantasy points.

PIR and minutes are retained because V0.3 will likely model them separately.

## 7.2 Head Coach target

Keep Head Coach evaluation separate.

Coach scoring is discontinuous because the fantasy rules use win-margin brackets.

Store:

```text
actual_margin
actual_win
actual_coach_fantasy_points
```

Do not mix player and coach prediction errors into a single aggregate metric.

---

# 8. Baseline models

V0.2.5 should deliberately contain several increasingly sensible baselines.

## Baseline A — season mean

For player p at round R:

```text
prediction =
mean(fantasy_points before R)
```

This establishes a simple reference.

## Baseline B — last N games

Run:

```text
last_3
last_5
last_10
```

where enough history exists.

## Baseline C — exponentially weighted moving average

Use an EWMA so recent games receive more weight.

The decay parameter should be configurable.

Example:

```bash
elf evaluate --model ewma --alpha 0.25
```

## Baseline D — V0.2 xPDK

Reproduce the current V0.2 calculation using only information available at the historical decision cutoff.

This is critical.

V0.2 becomes the first real benchmark.

---

# 9. Availability handling

Do not simply remove unavailable players from evaluation.

Create explicit categories:

```text
available
questionable
out
DNP
unknown
```

For V0.2.5, evaluate two separate concepts:

### Conditional performance

"If the player plays, how many points does he score?"

### Unconditional fantasy expectation

"Before the round, how many fantasy points should we expect from this player, including the probability that he does not play?"

This distinction will become central to V0.3 expected-minutes modeling.

# 11. Evaluation protocol

## 11.1 Walk-forward evaluation

Never randomly split basketball games.

Use chronological evaluation.

Example:

```text
Train/history:
2022/23 → 2024/25

Test:
2025/26
```

and within a season:

```text
Rounds 1..R-1 → predict R
```

The evaluation framework should support both.

## 11.2 Cold-start handling

Early-season players may have little or no current-season history.

Define a fallback hierarchy:

```text
current-season history
        ↓
previous-season history
        ↓
career history
        ↓
position/team prior
```

Record which fallback was used.

Do not silently mix cold-start and mature-player predictions.

# 12. Metrics

## 12.1 Point prediction

Primary:

```text
MAE
RMSE
```

Secondary:

```text
median absolute error
bias
```

Bias:

```text
mean(predicted - actual)
```

is particularly useful for detecting systematically optimistic projections.

## 12.2 Ranking

Because fantasy decisions are ranking-heavy:

```text
Spearman correlation
Kendall tau (optional)
Top-5 recall
Top-10 recall
Top-20 recall
```

Example:

> Of the 10 players predicted to have the highest score, how many actually finished in the top 20?

## 12.3 Value ranking

Eventually evaluate:

```text
predicted_points / quotation
```

against:

```text
actual_points / quotation_at_decision
```

Do not use post-round quotation in the denominator.

---

# 13. Fantasy decision metrics

This is more important than pure MAE.

For each historical round:

1. construct the player pool as known at the decision cutoff;
2. run the lineup optimizer using each model;
3. record the recommended lineup;
4. score it using actual results;
5. compare it with baselines.

Metrics:

```text
recommended lineup actual score
captain regret
sixth-man regret
bench regret
formation regret
```

The key comparison should eventually be:

```text
Season-average model
vs
Last-5 model
vs
EWMA
vs
V0.2 xPDK
```

# 15. Leakage tests

Create explicit tests such as:

### Future-stat leakage

Inject a player's future game with an extreme score and verify that the historical prediction does not change.

### Future-price leakage

Change the post-round quotation and verify the pre-round prediction is unchanged.

### Future-status leakage

Change a later injury/status event and verify historical features do not change.

### Round-boundary test

Ensure Round R's completed game cannot appear in a prediction generated before Round R lock.

These tests are more important than adding another model.

# 19. Exit decision for V0.3

V0.3 should not automatically become "more complex."

After V0.2.5 we should ask:

1. Does xPDK beat season average?
2. Does it beat last-5/EWMA?
3. Which players/roles does it systematically miss?
4. Is the largest error from minutes or per-minute production?
5. Does FDR improve ranking?
6. Does price improve fantasy decisions?
7. Is the uncertainty estimate calibrated?
8. Does a component model have enough evidence to justify the added complexity?

Only then should V0.3 architecture be finalized.

# 20. V0.2.5 Reported Benchmark (`E2025` Rounds 1–12), All vs. Active Metrics & Pricing Provenance

## 20.1 Scope of the Reported Benchmark (`E2025` Rounds 1–12)

The reported V0.2.5 benchmark evaluates **`E2025` Rounds `1–12`** (`12` rounds, `N = 288` all-listed court-player observations, `N = 282` active court-player observations with `minutes > 0`, and `N = 72` Head Coach observations per model).

It is **not** presented as proof of universal model superiority across all EuroLeague seasons; rather, it demonstrates that different evaluation metrics favor different baselines:

- **`xpdk_v02`**: achieves the strongest rank-ordering correlation (`Spearman = 0.678` on all listed players, `0.691` on active players, and `Value Spearman = 0.231`), while exhibiting a systematic negative level bias (`Bias = -1.97` all / `-2.08` active) because quotation-based scaling under-forecasts the `1.10x` (+10%) team win bonus.
- **`season_mean` / `ewma`**: achieve the lowest point error (`MAE = 3.75` / `3.87`, `Active MAE = 3.63` / `3.73`) and the strongest simulated reference-squad lineup scores (`199.13` / `198.62`), with `ewma` achieving the lowest sixth-man regret (`1.26`) and `season_mean` achieving the lowest captain regret (`1.36`) in the 12-round sample.
- **`last5`**: ties for the highest `Top-10 Recall = 0.74`.

## 20.2 All Listed Players vs. Active Players Only

| Model | Version | N (All) | All MAE | All RMSE | All Bias | All Spearman | N (Active) | Active MAE | Active RMSE | Active Bias | Active Spearman | Top-10 Recall | Value Spearman |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `season_mean` | `0.2.5` | `288` | `3.75` | `4.80` | `+0.12` | `0.638` | `282` | `3.63` | `4.50` | `+0.07` | `0.650` | `0.72` | `0.086` |
| `last5` | `0.2.5` | `288` | `3.81` | `4.87` | `+0.10` | `0.626` | `282` | `3.68` | `4.55` | `+0.04` | `0.635` | `0.74` | `0.067` |
| `ewma` | `0.2.5` | `288` | `3.87` | `4.91` | `+0.19` | `0.630` | `282` | `3.73` | `4.61` | `+0.14` | `0.640` | `0.73` | `0.053` |
| `xpdk_v02` | `0.2.0` | `288` | `3.81` | `4.83` | `-1.97` | `0.678` | `282` | `3.65` | `4.50` | `-2.08` | `0.691` | `0.74` | `0.231` |

- **All Listed Players (`N = 288`)**: Evaluates unconditional predictions `E[FP]` against realized outcomes where `DNP`/`out` players score `0.0` fantasy points (testing availability discounting).
- **Active Players Only (`N = 282`)**: Evaluates conditional predictions `E[FP | plays]` exclusively on players who logged `minutes > 0` (testing pure on-court performance accuracy).

## 20.3 Lineup Regret Simulation Scope

The lineup decision simulation (`avg_recommended_actual_score`, `avg_lineup_regret`, `avg_captain_regret`, `avg_sixth_man_regret`, `avg_bench_regret`, `avg_formation_regret`) runs the deterministic `optimize_court_lineup()` solver on a standardized 11-unit reference squad (`4G, 4F, 2C, 1HC`) each round. It is a **simplified single-round decision simulation**, not a full multi-round fantasy-season replay with dynamic transfer trajectories.

## 20.4 Historical Pricing Provenance & Coverage by Season

Historical fantasy quotations have weaker archival coverage than official EuroLeague box-score statistics. Every player-game row in `eval_player_games` records an explicit `price_provenance` category:

| Season | `official_snapshot` | `archived_fantasy` | `reconstructed` | `proxy` | `missing` | Total Rows |
|---|---:|---:|---:|---:|---:|---:|
| `E2022` | `0` | `0` | `0` | `360` | `0` | `360` |
| `E2023` | `0` | `0` | `0` | `360` | `0` | `360` |
| `E2024` | `0` | `30` | `330` | `0` | `0` | `360` |
| `E2025` | `0` | `30` | `330` | `0` | `0` | `360` |
| `E2026` *(live)* | `100%` via `elf update` | — | — | — | `0` | Live snapshots |

Because `Value Spearman` (`prediction / price`) depends on pre-round quotation fidelity, value-ranking metrics are reliable only when backed by `official_snapshot`, `archived_fantasy`, or verified `reconstructed` quotations and should not be treated as equally reliable on `proxy` seasons (`E2022`–`E2023`).
